## 一、结论先行

1. **P0 只有两件**：把 1.0.26 装到真机、验「选择文字」是否真恢复；把装机结果回填文档。这两件不做完，后面全是空中楼阁。
2. **P1 是 1.0.27 的两件事**：长消息跨页选字的回归（1.0.24 能力，被 1.0.26 回退掉了）；出包/分发一键化（今天 `git push` 连犯 3 次「本地成功、远端没动」）。
3. **P2 是稳定性债务**：待机耗电复测、全量测试口径扩围、AI 费用插件降级。
4. **P3 是实验**：分层宠物阶段 2、Live2D。宠物当前是整图动画、默认关，不进验收。
5. **明确不做**：跟随上游、凭据轮换（用户已决定暂缓）、批量改 Riverpod `Ref.exists`。

## 四、各项方案要点

### P0-1 · 1.0.26 真机验收「选择文字」

- 动作：手机下载 `1.0.26+11131613` 覆盖安装 → `bash tooling/check-device.sh` → 长按自己消息 → 选择文字 → 系统工具栏出现「复制/全选」并能选中。
- 通过标准：工具栏可弹出、可拖动选词、复制成功；AI 消息同样可选。
- 失败处理：记录机型/系统版本 + 截图，进 1.0.27 修复；**不在 1.0.26 上改代码**（Rule 7）。
- 影响面：无代码改动。

### P0-2 · 装机结果回填

- 动作：把装机版本、时间、通过项写进 `PROGRESS.md` 与 `PROJECT_STATE.md` 第 2/6 节；HANDOFF §3.5 状态改「已装」。
- 通过标准：四线一致性表六行全 ✅。
- 影响面：仅文档。

### P1-1 · 长消息跨页选字回归

- 现状：`SelectionArea` 在 `SingleChildScrollView` 内，选区不能跨出视口；1.0.24 曾把选区包到滚动层外，但导致「选择文字」走 OEM 菜单。
- 目标：既保留自定义 `SelectionToolbar`（复制/全选/翻译/⋯），又能跨页扩选。
- 方案（按优先级尝试）：
  1. `SelectionArea` + `SelectionContainer` 包裹滚动层，并给滚动视图加 `SelectionRegistrarScope` 桥接，保留自定义 toolbar；
  2. 若 toolbar 仍被 OEM 抢走，改用 `TextSelectionControls` 自定义 handle + `contextMenuBuilder`，在选区变化时手动定位；
  3. 兜底：长按进入「选字模式」，滚动时冻结选区锚点（伪跨页），保证可用性优先。
- 影响面：`app/lib/ui/chat/widgets/message_text.dart`、`message_menu.dart`、聊天滚动容器。
- 验收：>2 屏消息可从首行拖到末行并复制成功；自己/AI 双方一致；`test/chat` 全绿；新增 1 条跨页选区用例。
- 风险：与边缘手势（0–80dp）冲突，需真机双验。

### P1-2 · 出包/分发一键化

- 现状：本轮出包要手工 6 步（fetch/merge → analyze → test → build → 验签/哈希 → 复制 D → 飞书 APK → 文档双写），今天 3 次 push 假成功。
- 目标：`bash tooling/release.sh --patch` 一条命令完成，任何一步失败立即中止并打印原因。
- 要点：`set -euo pipefail`；push 后 `ls-remote` 比对 HEAD；哈希/大小写入 HANDOFF 模板；飞书上传返回 `version` 才继续；生成「出包回执」文本供直接粘贴。
- 影响面：`tooling/`（新增脚本）、HANDOFF §五 构建命令。
- 验收：跑一次 dry-run 与一次真实出包，回执与手工结果一致；人为断网时脚本必须非 0 退出。
- 风险：飞书 token/上传耗时；脚本需可重入（失败重跑不重复建版本）。

### P2-1 · 待机耗电复测

- 动作：满电或 80% 起，锁屏黑屏 20 分钟，记录前后电量与 `batterystats` 唤醒锁。
- 判定：≤2% 正常，关闭该项；≥5% 立案查 `dsh web`/proot 常驻唤醒。
- 影响面：无代码，先取证。

### P2-2 · 全量测试口径扩围

- 现状：每轮只跑 `test/chat`（1969 条），settings/star/ui_config 等目录未纳入。
- 目标：每轮至少跑「chat + 本轮改动目录」；发版前跑全量，全量口径写进 HANDOFF。
- 验收：全量跑一次记录通过/跳过/失败，失败项建 baseline 清单。
- 风险：全量耗时长，放后台跑并按 Rule 24 轮询日志。

### P2-3 · AI 费用插件健壮性

- 现状：`local-ai-cost` 读 `secrets.json`（600）；凭据缺失或接口失败时表现未定义。
- 目标：缺凭据显示「未配置」而非报错；接口超时降级为上次缓存 + 灰字提示；不打印密钥。
- 验收：删掉 `secrets.json` 后聊天页不崩、提示可点开配置说明。

### P3-1 · 分层宠物阶段 2

- 目标：真实闭眼眨眼（已有闭眼/正视切图）、随机小动作、点击反馈。
- 前置：确认切图命名与 offsets 可用；性能预算（聊天页 CPU 增量 <3%）。
- 不进验收，开关默认关。

### P3-2 · Live2D 实时宠物

- 前置：拿到 `.moc3` / `.model2.json` / 动作与物理；拆件本身不能直接跑。
- 路线 A 分层木偶（推荐，与 P3-1 同源）/ B 烘焙精灵图 / C Cubism SDK。
- 未满足前置不启动。

## 六、执行红线（沿用现有 Rules）

1. 有红测试不出包；要 waiver 必须在 HANDOFF 写明风险。
2. 出包后同版本不再改代码，修复进下一个 patch。
3. 构建前 `main` 必须等于 `phone`；装完跑 `check-device.sh`。
4. push 必须裸命令 + `ls-remote` 复核；`cp` 到 D 盘后 `grep` 版本号确认。
5. 一轮只收一个主题；版本号只在构建时 +1。
