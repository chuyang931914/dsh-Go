# 文档地图：谁记什么

> 2026-11-14 定。项目里五处都在写「状态」，不划清就必然漂——`hot.md` 曾写 1.0.27、实际已是 1.0.29，就是这个原因。

| 文件 | 唯一职责 | 不写什么 |
|---|---|---|
| `PROJECT_STATE.md` | **当前事实**：实机版本、仓库头、今天能做什么。新对话开机读它 | 历史、流程细节、教训 |
| `HANDOFF.md` | **怎么做**：环境、构建、签名、分发、排查步骤 | 当前版本号（会过期） |
| `UPGRADE_TABLE.md` | **每个版本一行**：buildNumber、大小、sha、装机状态 | 决策原因 |
| `PROGRESS.md` | **按时间的发生了什么**：出包、装机、反馈 | 规则、约定 |
| `BACKLOG.md` | **没做的事**：待办、已决定不做 | 已完成的事 |
| `~/.dsh/memory/facts.md` | **长期约定与偏好**（跨项目）：用户习惯、协作方式 | 项目版本、路径细节 |
| `~/.dsh/memory/lessons.md` | **踩过的坑 + 下次怎么做** | 项目进展 |
| `~/.dsh/memory/log/` | **流水**：当天发生了什么 | 结论（结论进 lessons/facts） |
| `~/.dsh/memory/hot.md` | **每轮必读的 10 条**：环境、分工、当前版本、自检命令 | 任何可以按需检索的内容 |

## 三条规则

1. **同一件事只在一处写全**，别处只放指针（「见 PROJECT_STATE 第 2 节」）。
2. **会过期的数字**（版本号、sha、字节数）只出现在 `PROJECT_STATE`、`UPGRADE_TABLE`、`hot.md` 三处，且必须同一次提交一起改。
3. 写完跑 `bash tooling/repo-check.sh`；它查版本号与版本表是否对得上。
